# Company Sync

Репозиторий комплекта: https://github.com/MOX-Studio/company-ai

Результат — артефакты из актуального `catalog.json` подключены к выбранной среде сотрудника, личные дополнения сохранены, доступ к рабочим источникам проверен. Список артефактов определяется каталогом, а не списком инструментов автора этого навыка.

## Найти среду и комплект

Определи клиент из текущей среды: Codex, Claude Code или другое приложение. При наличии нескольких клиентов настраивай текущий; второй добавляй, если сотрудник его выбрал. Если среда не даёт доступа к локальным файлам, используй поддерживаемое подключение рабочего пространства или передай конкретный шаг для локального агента.

Найди клон по пути `Источник общих правил` в общих инструкциях, в контексте текущей задачи или в `~/company-ai`. Проверь remote. Если клона нет, клонируй указанный репозиторий в свободную постоянную папку. Обычные недостающие Git/Python-инструменты устанавливай доступным доверенным способом.

Перед обновлением запомни список артефактов и версию из прежнего локального `catalog.json`, затем проверь рабочее дерево и текущую ветку. Для чистого клона основной ветки получи обновления через `git pull --ff-only`. Сравни прежний каталог с новым: исчезнувшие записи нужны для отчёта об отдельной очистке. При первом клонировании прежнего списка нет; не утверждай, что обнаружил все исторические установки. Сохраняй локальные изменения; если история расходится или выбрана другая ветка, объясни конкретное препятствие. Не создавай ветки и не делай reset в рамках синхронизации.

Прочитай `README.md`, `START_HERE.md`, `catalog.json` и профиль выбранного проекта. Все относительные пути далее отсчитываются от корня клона. Если выбран только один проект, используй его без дополнительного вопроса. При обновлении прочитай новую версию этого навыка из клона.

## Подключить артефакты

1. **Правила и навыки.** Для Codex или Claude Code выполни `python3 scripts/install.py --agent codex|claude --dry-run`, подставив одно значение. Проверь список путей, затем выполни ту же команду без `--dry-run`. Запрос сотрудника подключить или обновить комплект разрешает эту установку; повторное подтверждение для обычного добавления не нужно. Скрипт сохраняет текст вне управляемого блока и отказывает при конфликте путей.
2. **MCP.** Для каждой записи, относящейся к выбранному проекту, прочитай её `instructions`. Сначала проверь существующее подключение и доступ. При необходимости добавь сервер штатным механизмом клиента. Личную авторизацию проходит сотрудник. Не заменяй существующий сервер с другим адресом и не сохраняй токены в этом репозитории. Проверь чтение нужного источника, а не только наличие записи в настройках.
3. **Плагины.** Прочитай инструкции записей `plugins`, подходящих клиенту и проекту. Используй указанный проверенный источник и штатную установку клиента. После установки проверь доступность плагина. Пустой массив означает, что общих плагинов пока нет.
4. **Настройки.** Обрабатывай записи `settings` по их инструкции и области действия. Меняй только объявленные параметры, сохраняя прочие настройки и локальную резервную копию изменяемого файла. Несовпадение обязательной политики организации с пресетом — конкретный конфликт, а не повод обходить политику. Пустой массив означает отсутствие дополнительных пресетов.
5. **Контекст проекта.** Открой источники из профиля, прочитай текущие инструкции репозитория и доступные вводные материалы. Ссылки на Notion не предоставляют доступ автоматически. Закрытые материалы читаются через личное подключение и не копируются в публичный каталог.

Для неподдерживаемого клиента проверь актуальную документацию по расположению навыков, инструкциям и MCP; не переноси пути Codex/Claude вслепую. Если нужная возможность отсутствует, закончи независимые шаги и укажи точное ограничение.

## Проверить и передать результат

Для поддерживаемого локального клиента выполни `python3 scripts/install.py --agent codex|claude --check`. Эта проверка касается только общих файлов и ссылок. Отдельно проверь MCP, плагины, настройки и чтение проектных источников.

Укажи версию каталога и Git commit клона, клиент, что добавлено или уже актуально, какие личные настройки сохранены и что требует доступа сотрудника. Создание файла, активация навыка и успешное чтение источника — отдельные результаты. Предложи начать новую сессию для проверки загрузки общих инструкций.

Если артефакт исчез из каталога, не удаляй ранее установленную пользовательскую копию автоматически: сообщи о ней и предложи отдельную очистку. Не объявляй настройку полностью законченной при недоступном обязательном источнике.
