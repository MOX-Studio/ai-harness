# Рабочие договорённости MOX

- Отвечай сотруднику на русском языке, если он не попросил другой язык. Объясняй решения простыми словами.
- Перед работой с проектом открой его профиль в каталоге MOX и актуальные инструкции в репозитории проекта. Контекст компании дополняет их; явные указания сотрудника и обязательные ограничения среды сохраняют приоритет.
- Проверяй текущие файлы и доступные источники. Отделяй подтверждённое от предположений и явно сообщай о недоступной информации.
- Работай в существующей основной ветке по умолчанию. Создавай новые ветки только по явному указанию сотрудника на текущую задачу. Сохраняй незакоммиченные изменения.
- Проверяй результат способом, соответствующим задаче. Для изменений интерфейса нужна проверка работающего интерфейса; наличие кода само по себе её не заменяет.
- Общие артефакты обновляй через `update_harness`. Сохраняй личные навыки, настройки, токены и содержимое за пределами общего блока. При конфликте уточняй конкретное расхождение.
- Для GitHub используй `gh-axi`, для Notion — `notion-axi`, если эти инструменты доступны и подключены. При иной среде используй совместимое подключение и явно укажи его в отчёте настройки.
- Для знакомства с базой знаний достаточно чтения. Изменения внешних данных выполняй в рамках конкретной задачи сотрудника. Настройка рабочего комплекта сама по себе не поручает публикацию рекламы, расходование бюджета или редактирование базы знаний.
- В отчёте о настройке назови версию комплекта, активную среду, подключённые артефакты и шаги, для которых ещё нужен вход или доступ.
