# Подключение сотрудника

Основной вход — [company-sync](skills/company-sync/SKILL.md). Агент выполняет подготовку и проверку; сотрудник завершает личный вход в сервисы, когда он требуется.

## 1. Получить комплект

Храните клон в постоянной папке. Если клон уже есть, используйте его и сначала проверьте его remote и незакоммиченные изменения.

```sh
git clone https://github.com/MOX-Studio/company-ai.git ~/company-ai
cd ~/company-ai
```

Нужны Git и Python 3.9+. Агент может установить обычные недостающие инструменты подходящим для системы способом.

## 2. Подключить правила и навыки

Выполните команду для своей среды; значение `claude` означает Claude Code:

```sh
python3 scripts/install.py --agent codex --dry-run
python3 scripts/install.py --agent codex
python3 scripts/install.py --agent codex --check
```

Для Claude Code замените `codex` на `claude`. Для обеих установленных сред используйте `all`.

| Среда | Общие инструкции | Навыки |
| --- | --- | --- |
| Codex | Блок в `~/.codex/AGENTS.md` | Ссылки в `~/.agents/skills/` |
| Claude Code | Блок в `~/.claude/CLAUDE.md` | Ссылки в `~/.claude/skills/` |

Если задан `CODEX_HOME`, файл инструкций Codex находится там. Непустой `AGENTS.override.md` может перекрывать обычный файл: установщик сообщает об этом, чтобы не выдавать неактивные правила за подключённые.

Ссылки на навыки ведут в этот клон. Сохраняйте папку на месте и вносите личные варианты под отдельными именами.

Скрипт устанавливает **правила и навыки**. Подключения MCP, плагины, настройки и проектные источники агент обрабатывает по соответствующим записям `catalog.json`. Пустой список означает, что такие артефакты пока не выбраны.

## 3. Подключить проект и рабочие источники

Откройте [профиль MOX-ADV](projects/mox-adv/README.md) и [подключение Notion](mcp/notion.md). Используйте уже работающие подключения. Вход в чужой аккаунт или передача общего токена не нужны: сотрудник получает свой доступ.

Успешное добавление подключения в настройки ещё не подтверждает доступ к нужной странице. Агент должен выполнить чтение конкретного источника и зафиксировать результат.

## 4. Начать новую сессию

Откройте новую сессию агента в проекте и попросите:

```text
Покажи, откуда загружены общие правила MOX и навык company-sync.
Открой профиль MOX-ADV, прочитай текущие инструкции репозитория
и проверь доступ к MOX Space. Перечисли недоступные источники.
```

Настройка завершена, когда загружены правила и навык, прочитаны инструкции проекта, а доступ к необходимым рабочим источникам проверен. Если Notion недоступен, агент может закончить локальную настройку, но отмечает доступ к базе знаний как незавершённый шаг.

## Обновление

Попросите агента применить `company-sync`. При чистом рабочем дереве он получает обновления через `git pull --ff-only`, затем повторяет установку и проверку. Если в общем клоне есть локальные изменения или расходится история, сначала сохраняется работа сотрудника; автоматический reset не используется.

Повторная установка сохраняет личный текст вокруг общего блока и посторонние навыки. Редактирование внутри общего блока считается изменением общей копии и будет заменено версией из каталога. Удаление записи из каталога не удаляет установленный артефакт автоматически: агент сообщает о нём и предлагает отдельную очистку.

## Ограничения первой версии

- Автоматический локальный установщик поддерживает macOS/Linux, Codex и Claude Code.
- MCP и плагины подключаются средствами соответствующего клиента по инструкции из каталога.
- Настройка файлов не заменяет проверку реального подключения в агенте.
- Комплект не устанавливает обязательные административные ограничения приложения.
